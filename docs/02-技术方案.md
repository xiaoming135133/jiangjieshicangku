## 2.1 总体架构

三段式：手机端负责拍、看、改；云端负责理解、对齐、索引；平板与网页端负责整理与复习。三端共享同一个数据模型，因此任何一端做的修改，另外两端立刻可见——这也是赛题鼓励的多设备接力。

| 层 | 组成 | 职责 |
| --- | --- | --- |
| 采集端（Android） | 相机与矫正、版面预览、节点卡片、拖拽改挂 | 拍得正、看得清、改得动；所有自动结果在这里可被否决 |
| 结构端（云端） | 版面分析、公式识别、结构对齐、关系推理、检索索引 | 把一张图变成节点，并决定它长在树上哪个位置 |
| 整理端（平板 / 网页） | 知识树视图、关系图、错题本、复习计划 | 大屏上的重排与复习；平板可手写批注 |

数据模型只有四张表，刻意保持简单：素材（原始图与版面）、节点（知识点与题目）、边（关系）、修订（谁在什么时候改了什么）。修订表是「可回溯」和「修正即反馈」两个特性的共同基础。

## 2.2 功能概述

| 模块 | 功能 | 首版范围 |
| --- | --- | --- |
| 拍摄与矫正 | 自动裁边、去阴影、透视校正、多页连续拍 | 全量 |
| 版面与识别 | 文字/公式/图形/表格分区，公式转 LaTeX，保留原图 | 文字与公式；图形只做区域保留 |
| 结构对齐 | 四选一关系判定 + 理由 + 置信度 + 未归类箱 | 单门课程，三层树（课程/章/知识点） |
| 知识树视图 | 树形浏览、拖拽改挂、批量归类、节点合并 | 全量 |
| 关系图 | 以知识点为中心的关系网络，展示跨章节连接 | 只读，可点击跳转 |
| 题目结构化 | 五槽位拆解，错题本按知识点重组 | 覆盖选择与计算两类 |
| 复习闭环 | 按遗忘曲线排复习顺序，薄弱点优先 | 基础版 |
| 多端同步 | 手机、平板、网页三端一致 | 手机 + 网页；平板复用网页 |

## 2.3 关键技术

### 2.3.1 增量结构对齐

整条流水线分三步。每一步都为下一步留下可解释的中间结果，便于定位错误。

```
输入：新内容 x（一张图或一段识别结果）+ 当前知识树 T

① 候选生成（三路并行，各取前 10）
   语义路：x 的嵌入 与 所有节点标题+摘要 的嵌入 做近邻
   字面路：识别文本与节点标题、章节名做字符级匹配（中文短标题上这一路很有效）
   符号路：x 中的公式符号集合 与 各知识点高频符号集合 求交（理工科专用，命中率意外地高）

② 关系判定（一次结构化调用）
   输入：x 的摘要 + 候选节点及其父节点路径
   输出：{"relation": "挂载|扩展|新建|待定",
          "target": 节点 id 或空,
          "reason": "一句话理由",
          "confidence": 0.0–1.0}

③ 阈值分流（三个档位，行为不同）
   confidence ≥ 0.80  → 直接执行，并在卡片上标注「已归入 · 可改」
   0.55 ≤ conf < 0.80 → 执行，但标黄并出现在「待你确认」列表
   conf < 0.55        → 仅入未归类箱，不猜测
```

「符号路」是这套方案在理工科场景下的一个便宜而有效的偏方。学生问「这个公式在哪」，本质是在问符号；而符号集合的重合度对短文本标题极不敏感，恰好补上了语义路在短标题上的短板。

### 2.3.2 未归类箱与批量确认

这是整套交互里最容易被低估的设计。逐条询问会让用户在第 3 次就想关掉应用；而静默丢弃会让结构永远起不来。折中做法是**延迟决策**：

- **积累。​**置信度低于阈值的条目进入未归类箱，界面上只有一个数字角标，不打断任何操作。
- **聚类。​**箱内条目达到 3–5 条时，先在箱内做一次小聚类，把同类的归成一堆。
- **一次问完。​**以一堆为单位提问：「这三条看着像新的一章『级数』，要开吗？」用户一次点击处理三条。
- **可延后。​**用户也可以选择「再等等」，箱子上限设为 30 条，超过则提升提示优先级。

### 2.3.3 版面理解与公式管道

版面分区的目的不是好看，是为了让后续每一步只处理它该处理的部分：公式送公式识别、文字送文本识别、图形只保留区域。混在一起识别，是手写板书错误率高的主因。

| 步骤 | 做法 | 失败时的降级 |
| --- | --- | --- |
| 倾斜与裁边 | 角点检测 + 透视变换 | 保留原图，仅做亮度归一 |
| 分区 | 版面检测模型输出区域框与类别 | 退化为整页 OCR |
| 阅读顺序 | 按区域位置与栏数排序，处理双栏板书 | 按从上到下、从左到右 |
| 公式转写 | 公式区单独送识别，输出 LaTeX | 保留公式截图，允许用户手写修正 |
| 索引入库 | LaTeX 同时生成 MathML，建立符号索引 | 仅文本检索 |

### 2.3.4 修正即反馈

用户每改一次分类，系统记一条修订：原建议、最终选择、内容特征、耗时。这些数据有两个用途：短期用于调整该课程的阈值，长期用于构造一个真实分布的对齐评测集。

```
修订记录 {
  content_id, course_id,
  suggested: {relation, target, confidence},
  chosen:    {relation, target},        // 与 suggested 不同即为一次修正
  time_to_decide_ms,                    // 犹豫时间也是信号
  created_at
}

每周批处理：
  统计各课程的修正率与混淆对（如「扩展 → 新建」被改得最多）
  对该课程的对齐提示词追加 3–5 条少样本示例
  重新校准阈值：把修正集中的置信度分布下移 0.05
```

### 2.3.5 检索：三层召回

| 层 | 解决什么 | 实现 |
| --- | --- | --- |
| 语义层 | 「那个讲极限存在性的地方」 | 节点摘要与用户查询的向量近邻 |
| 符号层 | 「含 ε-δ 的那一页」 | MathML 符号索引，支持单符号与组合检索 |
| 结构层 | 「第三章下面所有跟连续有关的内容」 | 沿树与图遍历，支持按章节范围过滤 |

三层结果按统一分数融合后排序，展示时标明命中原因——让用户知道「为什么给你看这个」，是建立信任最便宜的方式。

### 2.3.6 复习闭环

节点带一个掌握度，由三件事共同决定：被复习的次数与间隔、相关题目的正确率、以及用户手动标记的「还不熟」。复习顺序按「遗忘风险 × 薄弱程度 × 考纲权重」排序，而不是简单的时间轮转。

这里刻意不做「自动出题」和「一键总结」。理由和 1.5 一致：赛题要的是助教，不是代做。让 AI 替你总结完，你只是读了一遍；让你自己看着薄弱点去翻原来那页，才是复习。

### 2.3.7 隐私与端云协同

- **原始图片默认留在本地。​**只有用户主动点「整理」时才上传，且上传后 24 小时清除。
- **云端只存结构化结果。​**节点、边、LaTeX 文本，不存原始照片。
- **可导出。​**全部笔记与结构可导出为 Markdown，兼容 Obsidian 的双链语法——我们不想做数据孤岛。
- **可离线。​**已同步的节点在本地可查可改，断网只影响新内容的整理。

最后一条值得多说一句：**支持导出成 Obsidian 格式**，看起来是在把用户送走，实际上是这个品类里最有效的信任建立方式。用户愿意把一学期的笔记交给你，前提是他随时能拿走。

## 2.4 工程质量保障

| 方面 | 做法 |
| --- | --- |
| 客户端 | Kotlin + Jetpack Compose，最低支持 Android 10；相机、矫正、本地 SQLite |
| 云端 | Python + FastAPI；版面与公式识别调用现成模型，不自研 |
| 模型 | 关系判定使用通用大模型接口，通过 JSON Schema 约束输出；所有结果带置信度 |
| 测试 | 对齐逻辑用固定知识树 + 固定输入做回归；识别链路录制真实照片做离线回放 |
| 可观测 | 每张图记录一条处理 trace：分区耗时、识别耗时、对齐置信度、是否被修正 |
| 规范 | 首周起启用分支策略、提交规范、静态检查与单元测试门禁；保留 AI 辅助编程的关键提示词 |
